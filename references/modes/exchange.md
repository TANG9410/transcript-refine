# 交流实录稿分支合同

## 目标

把商务、客户、销售、合作、访谈或普通多人对话整理成可回看、可追溯、仍像当时真实交流的实录。默认轻度精炼：清掉妨碍阅读的噪声，但保留原始顺序、话轮、措辞习惯、问答推进和态度强弱。

交流实录不是会议摘要，也不是把多轮对话改写成主题文章；它同样不是逐字照搬，明确的口吃、极端重复、ASR 错误和标点问题可以清理。

## 写稿前

1. 使用公共流程指定的事实源，不得用智能总结代替 `audio.original`、`web_page.content` 或用户原文。
2. 先校准人物关系、第一人称锚点和低置信策略。只有人物复杂且 ASR 标签不能稳定对应真人时才建立 `speaker-map.json`。
3. 长稿可沿原始时间线建立连续 `Sxx` 源段；一个源段必须对应连续的原文区间，禁止把不相邻发言收进同一主题。
4. 标出必须保留的问答、案例、数字、价格、解释、异议、承诺边界、不确定表达和下一步。
5. 用户没有指定精炼尺度时直接按轻度执行，不再追加确认；只有明确要求中度或重度时才切换。

## 精炼尺度

三档只改变口水词、重复和语序的清理力度，不改变信息删留标准。任何档位都不得跨话轮合并、跨时间搬运、概括成观点或列表、替换关键措辞、补写原文没有的结论。

| 档位 | 允许操作 | 使用条件 |
|---|---|---|
| 轻度精炼（默认） | 删除无意义口吃和极端重复；修正明确 ASR 错误；补标点、断句；只在原句附近做最小语序修补 | 用户未指定尺度时直接使用 |
| 中度精炼 | 在轻度基础上再去明显填充词、压缩紧邻同义重复；仍沿用原句结构和原有措辞 | 用户明确说“中度”或“更精简” |
| 重度整理（仍非摘要） | 在句内删除更多明确冗余和口头过渡，但仍保留全部事实、轮次、问答形式、态度词和关键措辞 | 用户明确说“重度”或“大幅清理” |

### 同一原文的三档对照

原始逐字稿：

> **唐玮：** 什么哦。然后那就是你你做销售的话，那你的一个节奏，就是说你你你获客啊什么的，就你你获客还是通过别人来介绍嘛。对吧？

轻度精炼（默认）：

> **唐玮：** 哦。然后那就是你做销售的话，那你的一个节奏，就是说你获客啊什么的，就是你获客还是通过别人来介绍嘛。对吧？

中度精炼：

> **唐玮：** 那你做销售的话，你的获客还是通过别人介绍嘛，对吧？

重度整理（仍非摘要）：

> **唐玮：** 你做销售，获客还是通过别人介绍嘛，对吧？

这个样例只校准清理力度，不能把“重度”理解为总结、归纳或信息删减。

## 输出合同

```markdown
# 标题｜交流实录稿

## 话题名称 [00:00:00-00:10:00]

**说话人：** 按原始话轮整理后的发言。

## 人物关系与低置信说明
仅在确有必要时提供。

## 疑似识别错误与修正说明
仅在确有疑点时提供。
```

硬要求：

- 事实源有可靠时间戳时，正文二级标题按原始时间递增，每个标题只覆盖一个连续时间区间；范围可用 `-`、`~`、`～` 或 `—`。
- 事实源没有时间信息时使用 `## 话题名称`，禁止编造时间范围；此时仍按原文段落和话轮顺序切分。
- 时间戳只放在大主题标题；独立时间戳和说话人行内时间戳均不合格。
- 只允许合并相邻、同一说话人、同一连续发言且中间没有互动的碎句；被其他说话人、时间段或话题隔开的发言不得合并。
- 保留发言先后、问答关系、追问、转折、分歧变化、案例展开和决策形成过程。
- 保留“可能”“我觉得”“不一定”“再看看”等语气强度和不确定程度，不得替说话人下更确定的结论。
- 禁止把多轮问答重写成观点摘要、分类列表、结论先行文章或复盘框架。
- 禁止为了显得专业或通顺而更换说话人的关键措辞、观点立场或表达风格。
- 销售观察、风险、待办和其他附录只能放在实录正文之后，不能替代正文，也不能改变正文顺序。
- 人物映射被用户纠正后，旧稿必须全局重检，不得只改一处姓名。

## 删留标准

三档共用同一“删除白名单”；中度和重度只能更积极地清理白名单内容，不能扩大删除类别。只允许删除：

- 不承载回应功能的“嗯、呃、啊、那个”等纯填充词。
- 同一句内的口吃和极端重复，如“你你你”“这个这个这个”。
- 紧邻出现、含义完全相同且没有互动作用的重复。
- 能够明确判断的 ASR 噪声；不能确定时保留并标注疑点。

必须保留：

- 有信息量的提问、回答、追问、反驳、案例、数字、价格、承诺和下一步。
- 解释过程、犹豫、保留意见、质疑、修正和必要回应词。
- 即使偏离主线，但能说明人物关系、业务背景、判断依据或现场语境的插曲。

不得因为某段“不够核心”“与主线关系不大”就整段删除。确属无语义的设备噪声或转写乱码可以删除；拿不准时保留原话并标注。

## 质量闸门

逐段回到同一时间位置的原文核对：

1. 每个发言块都能在原文相同时间位置找到依据。
2. 说话人轮次、问答顺序和时间顺序没有变化。
3. 案例、数字、解释、质疑、态度和限定条件没有被抽掉。
4. 没有新增事实、补结论、跨段拼接或主题化重写。
5. 成稿读起来仍像当事人在说话，而不是 AI 代写的商务文章。

开头、中段、结尾各抽一个高信息片段重点核对。保留率只作异常线索：轻度稿保留率高是正常现象，不得因为高于 80% 继续删字；如果成稿明显只剩原文的一小部分或连续多轮消失，必须回到原文逐段补回。

普通交流：

```powershell
python scripts/validate_transcript_artifact.py --mode exchange --draft refined.md --source original.txt --json
```

复杂多人交流必须追加 `--speaker-map`、`--people-count` 和 `--asr-channel-count`。确定性脚本只能检查格式，不能证明语义保真。

## 尺度异议时的校准

不要每次主动增加确认。只有用户表示“删得太多”“还是不够精简”或拿不准尺度时，才从本次原文选择三段：密集陈述、互动问答、方言或破碎口语。每段并排展示“原文 / 当前尺度整理后”，让用户选择：

1. 按此尺度继续。
2. 需要更精简。
3. 需要更保留。

收到选择后只调整清理力度，不改变主稿类型和信息保留标准。

## 失败模式与自修

- 只剩观点、要点或表格：判定为摘要化，回到原时间线补回完整问答和解释。
- 同一发言块混入不同时间位置内容：拆回原处，恢复真实话轮。
- 语言过于专业、简洁或确定：回滚到原措辞和原有语气强度。
- 有明显口吃和极端重复：只在原句附近继续机械清理，不借机重写整段。
- 未锁定人物却出现姓名：恢复低置信标签，重建人物表后全局复查。
- 为满足比例重复堆字或继续删字：停止按比例优化，改做逐段事实和顺序核对。

销售型交流需要判断客户顾虑和推进信号时，可追加读取 `../sales-review-transcripts.md`，但只使用其中的证据识别清单。不得把该文件的删除规则或“转写成业务补充”规则作用于实录正文；任何冲突均以本合同为准，附加观察只能放在正文之后。
