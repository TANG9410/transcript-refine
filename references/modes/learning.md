# 学习整理稿分支合同

## 目标

把课程、讲座、读书分享和知识型长独白整理成“详细知识叙事”：按知识关系重组，但完整保留讲解逻辑、原始案例、关键数据、限定条件、讲者风格和实质性问答。

它不是要点摘要，也不是逐句课程实录。

## 写稿前

1. 按自然话题建立 `Sxx` 源段清单，记录时间、讲者、主题和信息类型。
2. 建立课程地图：核心问题、概念关系、方法路径和案例分布。
3. 标出推理链、案例、数据、限制条件、现场演示和 Q&A。
4. 对直播运营与促销互动先分类，不得看到“营销”一词就整段删除。

## 三级互动处理

### 详细保留

- 讲者解释、推理过程和观点形成。
- 教学案例、现场演示、数据、方法步骤和适用条件。
- 学员或主持人的实质性 Q&A、反对意见和追问。
- 能反映受众画像或验证教学判断的投票、调研和反馈。
- 点赞、转发、评论等行为本身被用于教学分析时的内容。

### 压缩交代

- 直播规则、提问渠道和必要嘉宾背景。
- 等待观众、测试设备、重复拉群和重复会员权益说明。
- 只用于建立场景但不影响知识理解的主持串场。

通常压缩为一两句背景，不保留完整话术。

### 删除或从略

- 门票价格、会员促销、课程下单和重复 CTA。
- 单纯点赞关注、粉丝灯牌、报名和活动推广。
- 与知识主题无关的致谢、名单、场地和行程推销。

若促销段混有教学内容，只提取教学部分；正文写“纯商业促销内容从略”，并在覆盖表说明。

## 输出合同

```markdown
# 标题｜学习整理稿

## 基本信息
...

## 课程地图

- 知识主线：
- 方法路径：

## 一、知识主题 [00:00-00:15:00]

用完整段落保留讲者的解释和推理，不压成只有标题和项目符号的摘要。

### 核心概念与讲解逻辑
...

### 案例、数据与方法
...

### 限制、边界或易混点
...

### 实质性互动与问答
仅在源内容存在时使用。

## 源内容覆盖表
| 源段 | 时间/位置 | 处理 | 去向/理由 |
|---|---|---|---|
| S01 | 00:00-00:08 | 压缩交代 | 基本信息：直播规则 |
| S02 | 00:08-00:20 | 详细保留 | 第一章：核心概念 |
| S10 | 01:28-01:43 | 删除 | 纯商业促销内容从略 |

...
```

章节可按知识关系重排，但时间范围或 `Sxx` 去向必须可追溯。

## 质量闸门

- 每条核心结论都保留解释它的推理、案例或限定条件。
- 不能把案例只改写成一句结论，也不能把 Q&A 压成“大家进行了讨论”。
- 课程地图与详细章节必须一致。
- 覆盖表包含全部 `Sxx`，删除项必须说明具体理由。
- 开头、中段、结尾各抽一个高信息源段，核对讲者观点、数字、案例和限制。
- 保留率低于 35% 时警告可能摘要化，高于 80% 时警告可能原文搬运；比例不是通过条件。

运行：

```powershell
python scripts/validate_transcript_artifact.py --mode learning --draft learning.md --source original.txt --json
```

## 失败模式与自修

- 只剩知识点列表：补回讲解逻辑、原始案例、数据和限制。
- 返工后变成逐句实录：按知识关系合并表达，但保留证据。
- 把课程里的营销知识误删为促销：检查该段是否在解释用户行为、转化、内容策略或商业案例。
- 纯促销保留过多：压缩开场运营，删除门票、会员、下单和重复 CTA。
- 覆盖表与正文对不上：逐项核对 `Sxx` 去向，未覆盖即失败。

匿名回归基线：约 39,178 字课程被压成约 8,290 字要点时应判定过度摘要；约 28,009 字的详细版本属于正确方向，但仍须具备课程地图、三级互动处理和完整覆盖表。
