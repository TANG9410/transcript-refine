# 销售复盘型逐字稿整理

> 适用于：销售拜访、客户沟通、商务访谈、成交复盘、多条录音合并整理。

> 主稿边界：交流实录必须先读取 `modes/exchange.md`；复盘纪要必须先读取 `modes/review.md`。本文件只补充销售场景证据，不替代主稿合同。

## 核心判断

销售复盘型逐字稿不是普通会议纪要，也不是销售话术总结。它的价值在于保留能解释销售过程的证据：

- 客户为什么感兴趣
- 客户卡在哪里
- 销售方如何建立信任
- 价值如何被解释和验证
- 下一步为什么能推进或为什么卡住

所以精炼时可以删除口水词和无关插曲，但不能把业务证据压成笼统结论。

---

## 主稿与复盘层分开

商务销售对话默认先保证交流实录的过程证据。用户明确只要复盘、纪要或行动项时，主稿改为复盘纪要稿。两种情况都按以下优先级处理：

1. **先保留对话证据**：客户原话、反问、迟疑、认可、现场验证过程。
2. **再做通顺修正**：去口水词、合并残句、纠明显 ASR 错误。
3. **最后做复盘提炼**：交流实录场景放在可选附录；复盘纪要场景按事实、判断、风险、结论和行动项组织。

错误做法：

- 把客户顾虑改写成一句“客户关注 ROI”。
- 把现场演示改写成一句“双方讨论 AI 搜索”。
- 把销售方提出的策略误归属为客户需求。

正确做法：

- 正文保留关键问答和转折。
- 复盘区再提炼“客户顾虑”“销售回应”“推进机会”。

## 多源合并方法

多条录音/笔记不要直接拼接，要先做来源清单。

### 来源清单字段

| 字段 | 说明 |
|------|------|
| note_id | Get 笔记 ID |
| 标题 | 原始标题 |
| 时间 | 创建时间或录音时间 |
| 类型 | 录音卡、会议卡、普通录音等 |
| audio.original 长度 | 判断信息量 |
| 来源角色 | 主线、补缺、说话人校验、后置业务补充 |

### 合并顺序

1. **确定主线骨架**：选最连续、最完整、最符合时间线的一条。
2. **用高质量录音卡校正说话人**：录音卡的标签是线索，不是最终事实。
3. **用补充录音补缺句和业务细节**：尤其补客户顾虑、销售回应、下一步安排。
4. **把后置录音放入补充章节**：晚间、饭局、闲聊只抽取业务相关内容。
5. **去重但不压扁**：同一话题多次出现时，保留更完整的那次表达，用另一来源补足缺漏。

## 说话人归属

说话人归属是业务事实，不是排版问题。销售复盘里说错人，会直接影响判断。

### 判断依据

- 第一人称视角：我刚开始做业务、我们厂、我们销售、我们客户。
- 角色知识：谁是服务方，谁是客户方，谁是销售老板，谁是技术/运营。
- 问答方向：谁在提方案，谁在提顾虑，谁在确认落地条件。
- 上下文连续性：前后几轮话题是否自然接续。

### 标注规则

用户确认姓名后，正文用简单人名：

- 唐玮
- 张云
- 张总
- 郭师傅
- 运营陆晨

不要在正文里反复写“疑似”“工厂方”“销售老板”等说明。确实不确定的内容，集中放到末尾“不确定项”。

### 后验修正

用户纠正说话人或关键事实后，不能只搜索替换。必须重读受影响段落，检查：

- 这段前后的问答方向是否需要调整
- 章节标题是否因此变化
- 复盘观察里的判断是否需要改写
- 待办事项的责任人是否需要改

案例原则：如果“要打造标杆客户”是唐玮提出的，就应理解为服务方为了起步阶段建立真实案例而提出的策略，而不是客户方主动提出的要求。

## 销售复盘必须保留什么

### 客户业务现状

- 传统获客渠道
- 平台投流成本
- 客户来源和转化路径
- 老客户/转介绍/自然搜索/AI 搜索等渠道
- 销售团队配置和执行能力

### 客户顾虑

- 投入产出比
- 预算和试错成本
- 合同边界
- 是否真的能带来询盘
- 团队是否能接住线索
- AI 内容是否可信、是否能被推荐

### 销售动作

- 如何解释价值
- 如何类比传统 SEO/GEO/平台投流
- 如何现场验证豆包、通义千问等 AI 推荐逻辑
- 如何把抽象服务落到客户行业和产品
- 如何提出资料清单、后续对接、标杆客户打法

### 信任信号

- 客户主动追问
- 客户补充更多内部信息
- 客户愿意安排对接人
- 客户认可某个判断
- 客户提出下一步验证方式

### 下一步安排

- 对接人
- 资料清单
- 账号/后台/素材准备
- 时间点
- 责任人

## 可以删除什么

以下内容通常不进入正文：

- 接电话
- 查快递
- 临时改安全阀
- 仓库招聘
- 聚餐闲聊
- 健康、同学、人事情绪闲谈
- 与主线无关的生产杂事

但有例外：如果闲聊实际暴露了组织关系、决策链条、客户信任来源、销售推进条件，就应转写成业务补充，而不是整段删除。

## 销售证据补充模板

交流实录正文之后可追加；复盘纪要则把这些字段映射进 `modes/review.md` 的固定结构和证据锚点：

```markdown
## 精炼说明

- 已清理：口水词、重复表达、明显 ASR 错误、无关插曲。
- 已校对：说话人归属、关键术语、跨来源重复内容。
- 删除范围：接电话、查快递、生产杂事、人事闲聊等与业务主线无关内容。

## 销售复盘观察

### 客户现状
- ...

### 核心顾虑
- ...

### 有效销售动作
- ...

### 推进机会
- ...

### 风险与待确认
- ...

## 可执行待办

| 事项 | 责任人 | 说明 |
|------|--------|------|
| ... | ... | ... |
```

## 质量检查

交付前检查：

- 是否还像完整对话记录，而不是会议摘要
- 是否保留了客户顾虑的原始表达
- 是否保留了销售方关键回应
- 是否把说话人纠正同步到了正文、复盘观察和待办
- 是否把多源补充合并进正确话题，而不是堆在末尾
- 是否明确列出不确定项，而不是在正文里到处写“疑似”
- 是否避免把用户提出的销售策略误写成客户方诉求
