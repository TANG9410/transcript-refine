## 一、读书感悟笔记整理规范

### 核心原则

1. **不要 AI 总结，要逐字稿整理优化**
2. 去口水词、纠正识别错误、让文字通畅
3. 保留个人思考和感悟的原始表达
4. 结构清晰但不改变原始逻辑

### 教训

- **先判断用途再动手** — 能从商务对话、明确复盘意图或课程长独白判断时直接路由；只有真正无法判断时才显示三个主稿选项
- 逐字稿是核心资产，AI 总结只是辅助
- **先写再删，不要先删再写** — 更新笔记时，先确认 API 成功，再清理临时文件
- **创建新笔记而非更新原笔记** — 精炼版创建为独立新笔记（标题加 `[逐字稿精炼]` 前缀），原笔记完全不动。MCP `save_note` / `update_note` 均操作精炼稿，不碰原始录音笔记

## 二、录音卡对话式转写稿整理经验

### 录音卡笔记的特点

- 自带：智能总结、章节概要、逐字稿转写、发言回顾、金句精选
- 核心问题：智能总结不区分说话人，内容层层堆叠信息过载

### 整理目标

把录音卡从「AI自动生成的信息堆叠」转化为「结构化的对话访谈录」

### 关键操作

1. **确认"我"的身份**：
   - 根据对话上下文判断哪个说话人是用户本人
   - 用户本人标注为"**我**"，对方标注为"**说话人N**"
2. **按话题拆分**：交流实录标题格式 `## 话题关键词 [起止时间]`
3. **精简冗余**：只保留整理版+金句，删除AI自动生成的冗余层

### 关键决策

| 决策点 | 错误做法 | 正确做法 |
|--------|----------|----------|
| 说话人标识 | 混在一起 | 明确标注"我"和"说话人N" |
| 标题风格 | 陈述句 | 疑问句/对话式标题 |
| 内容取舍 | 保留所有模块 | 只保留整理版+金句 |
| 时间戳 | 不标注 | 每个话题标注起止时间 |
| 总结方式 | 一段式AI总结 | 按人物分段总结 |

## 三、长程课程录音稿整理经验

### 核心问题

长程录音（>1h）内容量大，需要两层笔记层级。

### 两层设计

**第一层：逐字稿（按主题分散）**
- 按课程主题/章节拆分
- 标题加序号：`课程名称（1/N）：主题一`
- 去口癖、纠错、加标题、保留风格

**第二层：方法论提炼（按维度整合）**
- 同一维度整合成一篇，不再拆分
- 标题：`XX 方法论提炼初稿（待细化完善）`
- 结构：核心原则 → 具体方法 → 案例参考 → 待完善项

### 类比

| 层级 | 类比 | 用途 |
|------|------|------|
| 逐字稿 | 菜市场原材料 | 完整但杂乱 |
| 方法论 | 菜谱 | 提炼过的规则 |

### 教训

- 方法论**不要再拆分**，碎片化不方便查阅
- 不同层级笔记的使用场景不同，不要机械套用"拆分"逻辑

## 四、笔记归类方法论：标题信号优先原则

笔记归类时，**标题是最强的信号**，优先根据标题判断笔记类别，再辅助以内容分析。

## 五、实践笔记改写公众号文章的经验

### 转写纠错原则

- 不是所有转写错误都需要修正，只修正影响语义理解的
- 修正时标注原文和修正理由
- 不确定的地方保留原文，加 `[?]` 标记

### 长文本处理

- 录音卡笔记是语音转写，识别率不高
- 需要基于话题背景、专业术语进行修正
- 避免基于错误转写生成内容

---

## 六、阶段性总结知识库整理规范

- 定期审视知识库内容
- 去除冗余和过时内容
- 确保同类内容归类正确
- 标题反映内容核心

## 七、常见错误速查

| 错误 | 正确 | 语境 |
|------|------|------|
| 说话人标注错误 | Get笔记 常把第三方名字错误标为说话人标签 | 需人工校正 |
| audio.original vs content | 录音类笔记原始逐字稿在 `audio.original`，`content` 是智能总结 | 整理前确认 |
| link 笔记取错字段 | link 类型（公众号直播、得到直播等）没有 `audio` 字段，原始逐字稿在 `web_page.content` | 按 note_type 选对字段 |
| 合并内容较长 | 整理版+原始版可能超16000字符 | API 可正常处理 |
| OPC / OBC 混淆 | 音频中"OPC"常被识别为"OBC"商业社区 | 注意区分语境 |
